# 测试记录入口

所有人工验收、Agent 回放与自动化验证都必须有独立运行记录。成功、失败、取消、超时
分别记录，不清空会话或覆盖失败结果来获得通过。

## 记录规范

- 原始产物统一放在 `.local-acceptance/test-runs/<runId>/`，不提交到 Git。
- 每次测试记录运行版本、测试来源、用例和预期。涉及 Mac/Core 的端到端验收或回放，
  开始前确认参与链路的记录均已就绪；未就绪不得请用户测试，不能以“之后再补录”替代。
- 纯本地单测、静态检查及配置验证使用命令记录，不启动或等待 Mac/Core；不适用的
  会话、模型和采集字段标为 N/A。缺失的应有证据仍须明确标记，不得改记为不适用。
- 端到端验收或回放每轮保存原始问题、最终转写、鼠标操作说明、采集请求及结果、发送和接收阶段、模型
  名称、工具参数和结果、grounding 决定、最终答案、错误和时序。用 run/session/turn/
  request/response ID 串联，保留重试次数和全部尝试。
- 原始音频不落盘，音频只记录格式、长度、时序与转写。截图只复用本轮已授权且完成
  隐私过滤的采集，不新增采帧，不连续监控。凭据、请求认证头和绝对秘密不得进入记录。
- 用户报告、UI 截图、真实工具结果和合成输入必须标明来源，不能互相冒充。
- 原始调试产物默认 24 小时过期。到期前完成分析并留下不含敏感原文的结论；排查未完时
  先确认必要的保留范围，不静默延长原图授权。不可因为记录工具失效就直接要求重复测试。
- 后续验收先从此入口进入，使用同一套记录工具；原有一次性图片留样及普通时序日志
  不能单独充当完整调试记录。Debug 模式不得自动把未知结果标为通过。
