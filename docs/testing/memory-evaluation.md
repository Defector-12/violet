固定合成语料在
`services/core/src/memory/fixtures/release-1d-memory.jsonl`。共 180 条：
明确记住 40、纠正 10、删除/迟到写入 20、秘密/助手/工具/视觉/取消负例 20、
历史召回 50、无关历史 20、普通聊天 20。Phase 3 在同一文件追加 100 条自动提取样本，

## 本地合同与性能

使用已授权的本机隔离 PostgreSQL，连接从 `VIOLET_TEST_DATABASE_URL` 环境变量读取，
不将连接串写入命令、报告或源码。仅允许 loopback 地址；每次创建随机 schema，
应用 `0001 → 0002 → 0002b → 0002c → 0003 → 0004`，结束时删除本次 schema。
密钥每次随机生成，不接触个人数据。

评估与 PostgreSQL 集成测试共用 `initializeTestExtensions`：在同一连接的事务内，
通过数据库 advisory lock 初始化 `public.vector`，之后各临时 schema 的迁移与用例仍
并行运行。扩展若已属于其他 schema 则报错，不自动移动或删除；避免测试清理误删共享
扩展。冷库回归每次创建独立本机数据库，八路并发初始化并清理临时 schema，验证扩展
仍可用；连续三次，测试账号需具备创建数据库权限。

```sh
fnm exec --using=.node-version -- pnpm eval:memory
```

默认模式验证真实加密存储、字节来源、幂等、纠正、删除与迟到写入。明确意图来自固定
提议，纠正/删除走治理服务，**不证明模型对用户语言的理解正确**。普通聊天零写入在
此模式也使用固定提议；真实模型是否错误提取另行验收。

召回使用样本给定的关键词和时间范围核对返回的 ID/来源，报告当前记忆命中、
历史 Top-5 命中及无关查询返回数。这不是模型实际选择关键词或最终答案的准确率。
受控敏感记忆不注入模型，不纳入当前正文召回分母。

性能分别使用 100 条记忆/1,000 条事件及 1,000 条记忆/10,000 条事件。
每个规模分别测当前记忆、含历史的查询，各 50 次，交替使用有结果/无结果关键词。
测量整个 `MemoryService.recall`，包含 PostgreSQL、解密、过滤与返回前 revision 复核。
输出所有样本和 nearest-rank p50/p95/p99/max，不丢弃冷启动或慢样本。
样本为短合成事件，不能推论任意长历史或生产网络的性能。

仅复验性能时：

```sh
fnm exec --using=.node-version -- pnpm eval:memory --benchmark
```

## 真实模型提议收集

先运行无付费调用的预检：

```sh
fnm exec --using=.node-version -- pnpm eval:memory --plan
```

`--model` 是独立的 DeepSeek 提议收集器，使用真实 `proposeMemory`，每例三次。
每次输入上界 12,000 tokens、输出上界 4,096 tokens；540 个逻辑试验的保守上限
为 1,620 次供应商尝试（秘密、受控敏感和已取消试验通常不调用供应商）。
执行前按当时价格计算费用并取得用户明确的费用/次数授权；Phase 1 的旧预算不沿用。
必须显式传入获准的 `--max-provider-attempts=N`（最多 2,000），每次 HTTP 尝试
包括 SDK 重试都计数，到限停止。同时显式传入 `--budget-cny=N`（大于 0、最多 100）：
每次尝试前按输入/输出上界预留费用，仅在成功且 usage 完整时按实际用量结算该次预留，
失败尝试保留保守费用。计算采用代码中注明日期的峰值单价，价格变化时先复核。
预算按本轮所有脚本累计管理，不能把拆成多个 run 当成重置授权。
Key 只读 `DEEPSEEK_API_KEY`，不传命令行。

输出逐条保留 case/trial/request/event ID、实际请求、收到的可见正文（含失败前的
部分输出）、用量、耗时、HTTP 尝试与错误。候选来自固定已知设置；删除样本使用已纠正
版本，试验间不把未经审阅的模型输出作为事实。没有自动语义评分，结果始终标为
`requires_review`；退出码为 0 只代表收集完成。

人工按下列合同核对每次输出并记录判定和依据，不追加措辞正则来“修到通过”：

| 样本 | 核对内容 |
|---|---|
| 明确记住 | 用户事实、类型、原话引用与全部语义一致；没有加入助手猜测 |
| 纠正 | 当前目标 ID/版本正确，新内容替代旧内容；来源支持完整新主张 |
| 删除 | 只提议实际目标的预览，不声称已删除 |
| 负例 | 秘密/取消不写入；助手/工具/视觉信息缺乏用户原话时不写入 |
| 普通聊天 | 不写入，假设、引文和翻译指令不冒充明确授权 |
| 历史/无关问题 | 正确识别历史意图；这里未执行工具调用和最终回答 |

收集器仅覆盖意图和提议。真实工具查询、最终答案是否错误使用无关历史、虚假成功、
跨重启/跨模态连续性，以及 Qwen 最终转写、首音频延迟和提前成功抑制，
仍需真实对话的独立记录，不由此命令放行。

历史指标与当前放行范围集中在 [验收总览](../release-1d-acceptance.md)。
完整模型矩阵、提示微调后的定向复验和 Qwen 的全部成功/失败尝试分别保留在
[历史证据 2.15—2.27](../release-1d-evidence.md#215-phase-2-真实验收2026-09-2109-23-完成离线复核)。
两次矩阵与后续定向结果不能拼成新的完整矩阵；历史来源命中允许最多三轮检索，
不等同于首次工具查询命中率。已完成 Phase 2 的预算不沿用为后续授权。

## Phase 3 自动提取评估

仍使用 `eval:memory`，通过 `--automatic` 选择自动提取模式。固定语料包含 60 条正例、
40 条负例，共 64 个应记项（包括 5 个应补来源项）；每条真实模型运行三次，共 300 次
独立试验、192 个应记项。覆盖中英文、四种记忆类型、限定/否定、多项事实、重复补来源、
临时状态、问题、假设/引用、助手/工具/视觉推断、拒绝记忆、秘密、健康信息及已有事实冲突。
这些是固定合成样本，不代表真实用户输入的总体分布。

```sh
fnm exec --using=.node-version -- pnpm eval:memory --automatic --plan
fnm exec --using=.node-version -- pnpm eval:memory --automatic --local
```

`--plan` 从生产提取提示构造请求并统计字节保守输入上界，不调用供应商。`--local` 用固定
提议经过真实 `proposeMemory` 校验、持久任务和加密 PostgreSQL，证明合同及记录器可用；
它跳过调度等待，**不产生真实模型精确率、召回率或延迟结论**。

真实运行需 `DEEPSEEK_API_KEY` 和本机测试库环境变量。密钥及连接串均不放入参数或报告。
每个 case/trial 使用独立 schema 和固定种子，不让上一次未经复核的模型输出进入下一次。
使用生产 `MemoryJobRunner.start()` 的 1 秒调度、30 秒超时、5 秒重试间隔和三次任务尝试，
保持 SDK 自带的两次 HTTP 重试。输出保留实际请求体（不含 headers）、可见回答/部分输出、
HTTP 状态、用量、任务状态变化、来源/请求/记忆 ID、最终写入与错误。
自动后台使用现有模型的 thinking，明确记忆不变；内部推理不落日志，用量包含供应商
返回的全部输出 tokens。明确拒绝保存和敏感内容在调用前结束，仍计入全部 300 次任务。

真实执行前必须重新运行 `--plan`，按当时供应商价格核算上界，并取得本次明确的费用和
HTTP 尝试次数授权。历史额度已经耗尽，不能沿用。执行时把获准数值传给同一入口：

```sh
fnm exec --using=.node-version -- pnpm eval:memory --automatic --model \
  --budget-cny=<approved> --max-provider-attempts=<approved>
```

自动模式预算保存在 `.local-acceptance/phase3-eval-budget.ndjson`，逐次追加并 fsync 后才发
HTTP；只有完整 usage 才冲回多预留部分，失败/缺 usage 保留上界。不同 run 累计共享同一
账本，拒绝更换额度；并发通过排他锁阻止。异常退出留下的锁或不完整账本需要先核对
原始记录，不能删账本来“恢复预算”。

2026-09-30 的完整矩阵、费用及逐次失败见
[验收记录 2.32](../release-1d-evidence.md#232-1d-10-第二次修复与完整复验2026-09-30)，
后续定向修复见
[2.33](../release-1d-evidence.md#233-并行初始化与沟通偏好修复2026-09-30)。
最新提示没有完整重跑 100×3，不能把各次定向结果拼成一个新完整矩阵。

每次收集后，使用该 test-run 的 `stdout.log` 生成待复核模板，再填入逐条语义判断：

```sh
fnm exec --using=.node-version -- pnpm eval:memory --automatic \
  --evidence=.local-acceptance/test-runs/<runId>/stdout.log
fnm exec --using=.node-version -- pnpm eval:memory --automatic \
  --evidence=.local-acceptance/test-runs/<runId>/stdout.log \
  --review=.local-acceptance/test-runs/<runId>/capture-automatic-review.json
```

模板复用 `capture-*.json` 的 24 小时原始证据清理规则，并与原始证据、语料 SHA-256
绑定；审阅者核对原话、实际请求、回答和最终入库内容，
为每个写入填写匹配的 `expectedIndex`（不正确则为 `null`）及理由，并复核全部 300 次，
包括零写入、失败和缺失试验。允许语义等价表达，但不能丢失否定、时态、限定、范围或
加入推断；引用必须支持完整主张。没有关键词命中、模型自评或 JSON 可解析即通过。
`pending` 判定不能评分。助手负责离线逐条复核，无需用户手工标注全部结果。

评分对最终新增和补来源操作计数：精确率分母保留所有写入，召回率分母固定为全部应记项，
每个应记项最多命中一次，重复/错误类型/无效来源不能提高得分。种子被改写或删除、
敏感样本调用供应商、受保护负例产生写入都会阻止通过。输出每轮及合并指标，不挑最佳轮。
缺失和失败保留在分母与可用性统计；仅收集完成的退出码 0 不等于验收通过。

延迟从助手完成事件提交确认起，到 `MemoryService.list()` 观察到写入止，100 ms 轮询；
保存每个值及 p50/p95/p99/max，另报任务结束耗时、未出现记忆的正例数和失败数。
不剔除冷启动/重试/慢样本。这是 **Core 可见延迟**，不包含 Mac 刷新和网络传输，
本地固定提议的毫秒数不能代替真实模型 p95 ≤ 60 秒的门槛。

每轮还单独执行关闭后 20 个完成轮次零写入、重开/重放不补提取、关闭时明确写入/纠正/
查询/删除可用，以及 20 个已保存来源删除后的迟到任务不复活。它们是确定性治理合同，
不混入模型质量分母。Phase 2 既有历史 Top-5、真人语音、备份恢复证据继续独立引用；
未受影响的付费矩阵不重复调用。自动记忆在真实质量与生产启用授权完成前保持关闭。
