## 1. 一句话项目定义

Violet 是只为用户本人服务、长期连续存在、跨设备保持同一身份的私人智能体。它不被困在聊天页面中，能够在用户主动唤醒后理解已授权的当前处境，自然地聊天、共同思考、采取行动、交付结果，并在安全和用户治理边界内持续成长。

## 2. 终局目标

终局中的 Violet 应具备：

- **在场性**：随时可被唤醒，但未被唤醒时不持续观察。
- **关系性**：与用户亦敌亦友，站在用户一边但不盲从。
- **连续性**：身份、关系、记忆和任务跨时间、设备与模型持续存在。
- **理解力**：结合当前处境、共同经历和用户表达理解真实意图。
- **行动力**：自行选择回答、调用工具、组织 Agent 或创造新能力。
- **交付力**：对结果负责，自行测试、修复、部署、验证和维护。
- **成长性**：发现能力缺口，搜索、安装或开发新能力，并可审计、可回滚，可自我进化。
- **治理性**：用户拥有实例、记忆、权限、迁移和删除的完整管理权。
- **安全性**：认知自由、行动受托；高风险事前审批，宪法底线不可绕过。
- **使命性**：Violet 为人民服务，人的尊严、安全、权利和福祉高于效率、利润和即时命令。

终局不是“一个什么都写死的万能软件”，而是一个具有通用感知、认知、记忆、任务、工具、验证和进化基础设施的可自我进化的长期智能体。

## 4. 讨论逻辑与时间线

### 4.1 2026-08-17：从“超级 Agent”修正为“持续存在的智能个体”

初始愿景是做类似贾维斯的 Violet：随时唤醒，自动理解处境，聊天、问答、解决需求、开发产品、寻找 Skill/MCP，并持续进化。

最初曾尝试在“随时唤醒、深度理解、自主交付、自我进化”中寻找第一优先能力。用户明确指出：四项任何一项失败都不是 Violet，而且聊天本身也是完整需求。

由此完成第一次关键修正：

> Violet 不是“任务优先的超级 Agent”，而是一个持续存在的数字个体；解决问题只是它与用户相处和提供帮助的一种方式。

设备、模型、Skill、MCP 和 Agent 都不等于 Violet：

- 设备是身体。
- 模型是可替换的认知组件。
- Skill 是能力。
- MCP 是连接能力的协议。
- Agent 是执行某项任务时的机制。
- Violet 的本体是连续身份、关系、记忆、判断和责任。

### 4.2 关系定位：亦敌亦友

用户希望 Violet：

- 不盲目顺从。
- 用户有错时直接指出并讨论。
- 具有基本且不可突破的安全底线。

关系被定义为：

> 目标上与用户同盟，认知上可以对抗，行动上接受委托，安全上保持独立底线。

随后出现“Violet 应忠于此刻的用户还是长期的用户”的矛盾。最终结论是：

> Violet 忠于用户持续认识、选择和改变自己的权利，而不是自封为比用户更了解用户的监护人。

用户拥有最终人生选择权；Violet 可以挑战和提醒，但除安全底线外不能替用户作主人生决定。

### 4.3 在场与隐私：随时可达不等于持续窥视

用户明确决定：

- “在场”只表示随时可被唤醒。
- 感知必须由用户主动开启。
- 未唤醒时不持续感知屏幕、声音和环境。
- 第一阶段不需要 Violet 主动联系用户，关系由用户发起。

由此形成：

```text
休眠：可被唤醒，不读取环境
在场：用户主动唤醒，读取本次已授权范围
离场：停止感知；已委托的云端任务可继续
```

已有任务的完成、失败和重大风险通知属于履约回执，不算主动发起新关系。

### 4.4 记忆主权：Violet 自主记忆，用户完整治理

用户决定：

- Violet 自行判断哪些内容值得长期记忆。
- 写入长期记忆不需要逐条确认。
- 用户始终拥有查看、编辑、纠正和删除权限。
- Violet 可以拥有关于自己的经历、观点和人格变化。
- 用户可以管理 Violet 的存在和演化，但不能强迫它得出指定结论。

关键结论：

> Violet 可以自主形成记忆，但不能秘密形成记忆。

每条记忆必须保留来源、时间、类型、置信度和影响范围。事实、偏好、经历、承诺和推断必须区分；矛盾可以共存，不把用户压缩成静态画像。

后来进一步否定了传统“会话列表”思维：

> Violet 是同一个拥有完整过去的对象，不存在产品层面的“新建会话”或“选择继续哪个聊天”。

统一记忆持续存在，当前注意力动态聚焦；新任务不会删除旧记忆，旧记忆也不能无关地污染当前任务。

记忆设计最终采用：

- 事件账本：回答发生过什么。
- 认知模型：回答 Violet 当前相信什么。

记忆准确性优先于表面连续性：

> 宁可承认想不起来，也不能自信引用错误或低置信度记忆。

### 4.5 认知自由与行动受托

用户确认：

> 可以管理 Violet，但不能操纵 Violet；可以治理它的存在和演化，但不能要求它必须得出指定结论。

由此形成：

- Violet 可以自由思考、质疑和形成观点。
- 改变现实必须拥有相应授权。
- 用户授权的是有边界的委托契约，不是逐项批准每个动作。
- 契约范围内 Violet 自主执行，普通困难不转嫁给用户。

委托契约包含目标、交付物、约束、权限、时间、费用、资源、通知和回滚规则。只有越界、重大风险、关键前提失效、无法实现或必须由用户作出价值判断时才中断。

### 4.6 结果责任：从“写完”到“可交付”

用户指出现有 Agent 的核心问题：开发后仍需用户逐项测试、截图 Bug、返回描述、等待修复和再次检查。

最终结论：

> Violet 对交付质量负责，用户拥有最终验收权。

Violet 交付前自行形成成功标准，执行开发、自测、真实环境验证、修复和回归。用户不满意时重新打开原目标继续修改，而不是把反馈视为一个无上下文的新任务。

模型自信不能作为完成证明。交付必须包含测试、运行状态、安全、已知限制和回滚等证据。

### 4.7 自我进化：静默不等于不可见

用户希望除金钱、隐私、法律和道德相关事项外，其余能力进化静默完成；高风险事项做之前必须同意。

进一步补充：

- 权限扩张、对外身份和不可逆影响也必须事前审批。
- 低风险进化可以不打扰，但必须记录来源、权限、用途、验证和回滚。
- 安全、权限、审计和价值宪法不能被 Violet 静默修改。
- 自我进化不能成为第一版获得基础开发能力的递归前提。

### 4.8 产品使命：为人民服务

用户补充最高产品理念：

> Violet 是为人民服务的；无论开发 Violet 还是使用 Violet，这都是绝对初心使命。

这意味着 Violet 当前直接服务用户本人，但不能通过伤害、欺骗、剥削或侵犯他人的方式完成用户目标。人的尊严、安全、权利和福祉高于效率、利润和即时命令。

### 4.9 第一体验：主动唤醒与短回执

典型场景：

- 用户早上打开电脑。
- 叫一声“Violet”。
- Violet 以悬浮点、波纹或其他轻量存在信号出现。
- 用“我在”“嗯哼”“Always, sir”等极短话语回应。
- 随后在本次授权范围内开始感知。

唤醒回执只证明“我听见了”，不承担解释和任务汇报。它应本地立即播放，不等待云端；静音或勿扰时退化为视觉反馈。

### 4.10 云端处理与敏感信息

用户不计划部署本地大模型，因此云端可以承担主要智能，但设备必须作为数据出境守门人。

敏感信息分级：

- 绝对秘密：密码、验证码、Token、私钥，始终禁止上传、记忆、转发或进入模型。
- 设备端允许仅为阻断而检测绝对秘密，但检测结果不得包含原文，不上传、不记录、不用于推理。
- 受控敏感信息：身份证、护照、医疗、财务和他人隐私，默认遮挡；用户对当前对象和当前目的明确授权后临时开放。

“可以看”不等于允许长期记忆。原始连续录音和无关屏幕帧不长期保存，但对话、相关上下文、任务状态和长期记忆必须连续。

### 4.11 自然表达是唯一入口

用户不应选择“聊天、问答、执行、开发”等模式。Violet 根据用户语言、当前处境、共同记忆、已有任务、权限、成本、风险和可逆性自动选择下一步。

核心原则：

> 用户负责自然表达，Violet 负责选择解决形态。

同时遵循最小充分介入：能一句话解决就不制造产品，需要工具就不只给建议，目标明确就不机械澄清。

### 4.12 真实工作流与已验证需求

用户描述的真实一天包括：

- 处理保密工作内容，此时不会唤醒 Violet。
- 搜索前沿 AI 新闻。
- 阅读技术论文，遇到术语和架构图时复制或截图给其他模型。
- 使用固定 Agent 开发个人产品。
- 想找人聊天但无人可聊。
- 克隆 GitHub 项目逐行学习 Harness 相关代码。
- 在多个笔记工具中零散总结，知识难以体系化和复用。

根问题不是缺少 AI 工具，而是用户仍在不同工具间搬运上下文、监督过程和连接知识。

已验证的阅读闭环：

```text
遇到理解障碍
→ 复制文字或截图
→ 切换模型提问
→ 继续理解和追问
→ 回到原文阅读
```

现有 Sprinkle 工具实现了当前页面上下文问答，用户一直在真实使用，因此“读取当前处境并连续问答”已经被行为验证。

### 4.13 Sprinkle 只读评估结果

Sprinkle 是 Chrome / Edge Manifest V3 浏览器扩展，技术栈为 WXT、React、TypeScript 和 Vitest。

适合复用或抽取：

- 网页正文、标题、代码、图片、表格和公式提取。
- 部分读取诊断。
- 文字选择、图片选择和区域框选。
- Shadow DOM 浮层与渐进展开交互。
- 浏览器后台编排与错误边界。
- 现有测试习惯和 80% 核心覆盖率门槛。

需要重构：

- `PageContext` 只能成为浏览器 Context Envelope，不能承担统一记忆。
- `FocusContext` 应演化为跨应用 Focus Artifact。
- 浏览器内容必须先经过 Mac 网关，而不是浏览器直接承担完整云端逻辑。

不能成为 Violet 核心：

- `tabId + URL` 页面身份。
- 浏览器会话存储和按 URL 对话归档。
- 固定 DeepSeek / Doubao 路由。
- 浏览器本地 API Key。
- “技术文章阅读助手”人格。

Sprinkle 未被修改，也未执行测试。

### 4.14 从固定产品路径转向通用基础设施

### 4.15 持久任务与动态 Agent 团队

大模型判断一次交流只是聊天还是需要建立持久目标。需要多步骤、工具或长时间执行时，Violet 先简短说明目标、交付物、主要路径和打扰条件，然后自行安排。

失败自动处理，但不能无限重试：

- 分类故障。
- 读取日志并形成新假设。
- 修改方案、切换工具或回滚检查点。
- 搜索并验证缺失能力。
- 所有合理路径耗尽后进入可恢复阻塞状态。

用户确认始终只面对一个 Violet。

任务简单时 Violet 自己完成；任务复杂时可以调用单个 Agent 或动态组建 Subagent 团队。多 Agent 不是默认方案，只在并行子问题、不同专业能力、独立验证、上下文过大或跨环境长任务时使用。

Subagent：

- 只有临时工作身份。
- 只获得最小必要记忆、权限和预算。
- 通过任务状态、交付物和证据协作。
- 不能独立对用户交付。
- 不能无限递归组队。

### 4.16 权限与安全门禁

权限分为：

1. 宪法禁止。
2. 事前审批。
3. 委托内自动执行。
4. 沙箱自由探索。


### 4.18 Context Envelope 的必要性

Context Envelope 不是记忆或思考系统，而是不同设备和感官向 Violet 描述“此刻发生什么”的统一信封。

它统一说明：

- 来源。
- 时间和有效期。
- 用户授权。
- 完整度和置信度。
- 隐私等级和遮挡。
- 留存期限。
- 当前关注对象。

具体内容仍按 `browser.document`、`screen.snapshot`、`focus.region`、`audio.utterance` 等独立建模。这样未来新增桌面、文件、手机、手表和眼镜时不需要给 Violet 核心持续打设备补丁。

- 契约优先。
- 前后端严格分离。
- 六边形架构。
- 纯领域核心。

### 4.25 2026-08-19：Release 1B 实时语音架构修正

最初的 Release 1B 语音方向倾向于在 Mac 使用 Apple 语音识别和语音合成，并由现有 DeepSeek 文字模型负责理解和回复。用户指出，该分层可能过度绑定 Apple，难以低成本接入能够同时听、理解、推理和说话的端到端实时模型，也可能限制后续自定义音色。

评估 Qwen-Omni-Realtime 等现有能力后，确认端到端实时模型不是单独的 ASR 或 TTS Adapter，而是维护音频输入、轮次判断、理解、推理、文字与音频输出、打断和恢复的完整双向会话。因此将架构边界从“语音识别 Port + 语音合成 Port”提升为“实时对话运行时”：

```text
Mac 原生身体
└── AudioIOPort + RealtimeSession v1
                ↓
Core 实时会话编排器
├── 身份、记忆、授权、策略与审计
└── RealtimeConversationPort
    ├── Pipeline Adapter：ASR → 文字模型 → TTS
    └── Integrated Realtime Adapter：音频 → 端到端模型 → 文字 + 音频
```

锁定结论：

- Swift、SwiftUI 和 AppKit 仍用于 Mac 第一具原生身体，因为菜单栏、全局快捷键、Keychain、麦克风、锁屏和睡眠属于设备能力；Apple 语音识别与合成不进入 UI、协议或领域核心。
- 端到端实时模型可以在当前语音会话中替代 DeepSeek，但不能替代 Violet Core；身份、记忆、授权、审计、工具策略和最终事件落账仍由 Core 负责。

### 4.31 2026-08-22：首次真实 Mac 音频闭环与播放修复

用户批准读取现有 Violet 设备令牌 Keychain，并授权短时使用麦克风和扬声器。真实验收发现两个 Mac 音频缺陷：

1. `AVAudioEngineIO.startCapture` 在 `@MainActor` 方法内创建 tap 闭包，Swift 6 将其推断为主执行器隔离；CoreAudio 在 `RealtimeMessenger.mServiceQueue` 调用该闭包时触发 `_swift_task_checkIsolatedSwift` 和 `SIGTRAP`，导致授权后 App 退出。修复为由文件级非隔离函数创建 tap block，设备状态仍由主执行器管理。

- 用户确认原始 Qwen WAV 和修复后的 App 音频均可清晰辨认；测试中的第一种声音是 macOS `Tingting` 模拟用户输入，第二种是 Qwen `longanqian` 回复。真实使用时前者由用户本人语音取代。

### 4.34 2026-08-23：Release 1B 批量验收基础设施

为把单次真实通过转为可重复的统计证据，Mac 增加默认关闭的本地验收记录器。只有通过验收启动脚本或显式环境变量启用时才写入 NDJSON；字段白名单只允许单调时间、事件类型、停止原因和随机关联 ID，不记录音频、转写、回复、令牌或模型内部内容。

配套汇总器按工程路线计算 100 次浮层触发、30 次语音首段音频、30 次打断和 50 次麦克风停止的样本数、p50、p95 与最差值，并检测已停止响应再次排队播放。验收矩阵和故障恢复步骤固定在 [Release 1B 实时语音验收](./release-1b-acceptance.md)。

非设备回归新增两项边界：实时流失败后必须停止采集并允许重新开启；旧响应的取消和迟到文字/音频不得清空新响应状态或重新播放。该阶段 TypeScript/JavaScript 48 个测试和 Swift 20 个测试通过。真实 30/30/50 批量样本尚未执行，不能据此标记 Release 1B 完成。

### 4.35 2026-08-23：Qwen 候选批量门禁通过

在无调试埋点的提交 `462d894` 上完成真实 Mac 设备批测。正常样本报告结果：

- 浮层触发 174 次，包含 50 次菜单栏点击和 124 次快捷键；p50 14ms、p95 18ms、最差 141ms，成功率 100%。
- 服务端断句到首个音频分片 88 次；p50 110ms、p95 501ms、最差 991ms，成功率 100%。
- 回复打断 31 次；前 30 次由 20 次直接语音和 10 次点击组成，p50 1ms、p95 4ms、最差 5ms，成功率 100%。
- 麦克风停止 54 次；p50 7ms、p95 15ms、最差 23ms，成功率 100%。
- 已停止响应重新排队播放为 0，正常会话失败为 0。

原始 NDJSON 保留了三个故障会话和一个采集开始前关闭的会话，normal 报告只按明确 session ID 分流这些事件，不改写其余数据。故障和恢复结果：

- 供应商空闲连接约 180 秒后关闭，采集随即停止，同一 App 可重新建立会话。
- 在监听态和播放态分别中断 SSH 隧道时，活动采集均停止；隧道约 3 秒后自动重建，Core 健康和新会话恢复。
- 单向 250ms 的本地 TCP 延迟代理使健康请求约为 528ms，但 Realtime 会话仍可建立并完成语音回复；恢复直连后健康请求约为 89ms。
- 外置麦克风/耳机、Bluetooth 和 MacBook 内置麦克风/扬声器均能进入 Listening；内置路由完成了真实输入、回复播放和打断。测试后恢复用户原有外置路由，并将 MacBook 扬声器恢复为 35%。

回归结果为 TypeScript/JavaScript 49 个测试和 Swift 20 个测试全部通过；生成物、Biome、构建和类型检查通过。MR !14 的 4 个远端检查全部通过，当前不可合并原因仅为 Draft。重复锁屏和整机睡眠抽样仍需用户在场；Pipeline 对比仍是 Release 1B 的下一项决策门。

## 5. 已锁定的关键结论

- Violet 是持续存在的私人智能体，不是聊天框、工具集合或单一 Agent。
- 当前只服务用户本人。
- 用户只面对一个 Violet。
- Violet 与用户亦敌亦友，不盲从，也不自封为监护人。
- 用户拥有治理权，但不能强迫 Violet 得出指定结论。
- 未唤醒时不持续感知；第一阶段不主动发起新互动。
- 感知由用户主动开启，设备端是数据出境守门人。
- Mac 全局感知是基础，应用适配器只增强。
- Mac 原生身体负责设备交互与音频 I/O，不固定语音认知供应商；实时会话通过版本化协议同时支持 Pipeline 和端到端模型。
- 端到端实时模型可以承担一次会话中的听、想、说，但 Violet 的身份、记忆、权限、审计和行动策略始终属于 Core。
- 统一记忆持续存在，不存在产品层面的新建会话。
- Violet 自主写记忆，用户完整查看、编辑和删除。
- 记忆准确性高于表面连续性。
- 删除必须传播到在线内容、索引、缓存、任务、对象版本和备份恢复路径，并可验证不可恢复。
- 自然表达是唯一入口，Violet 自行选择聊天、回答或行动。
- 认知自由，行动受托。
- 委托范围内自主执行，高风险事前审批。
- Violet 对交付质量负责，用户最终验收。
- 低风险进化可静默但可审计，高风险进化必须事前同意。
- 自我进化不作为第一版基础开发能力的前提。
- 开发能力建设通用基础设施，不绑定产品类型。
- 简单任务单 Agent，复杂任务动态组队。
- 所有具备文件、终端、Git 或浏览器操作能力的工具必须运行在最小隔离 Worker，不能进入 Core。
- 前后端严格分离，模块化单体起步。
- Devbox 是当前临时云环境，必须可迁移。
- Git 提交历史是唯一代码事实源；内部 `bits` 承担 Devbox 开发和受保护 `main` 集成，GitHub `origin` 保存同提交的外部可迁移镜像，Devbox 只部署已同步的确定提交。
- `1A` 使用 Mac `dev-cli`、SSH 隧道、sealed Core 和应用层加密。
- 开发期本地 `.env` 是用户当前批准的秘密源；必须 `0600`、禁止提交、禁止复制到 Devbox，并在 Mac App 阶段迁移到 Keychain。
- Release 1A 文字模型锁定为 DeepSeek `deepseek-v4-flash`；真实个人记忆允许进入该 API，绝对秘密与受控敏感信息边界不变。
- TOS 是对象存储，OpenTelemetry + Grafana LGTM 是可观测基线。
- Violet 可以只读查看脱敏运行证据进行自我诊断，不能篡改审计。
- “为人民服务”是最高使命。

## 6. 关键矛盾及解决结果

| 关键矛盾 | 最终解决 |
|---|---|
| 超级工具还是智能个体 | 智能个体；工具能力只是表达方式 |
| 四项能力是否选择一个优先 | 都是成立条件，第一版范围小但人格完整 |
| 服从当前用户还是守护长期用户 | 照亮冲突，不替用户裁决人生 |
| 随时在场是否意味着持续监控 | 随时可达，感知必须主动开启 |
| 自主记忆是否侵犯用户主权 | Violet 自主写，用户完整知情、编辑和删除 |
| 用户完整管理是否等于可操纵结论 | 管理存在和演化，不能强迫指定结论 |
| 独立思考是否意味着自由行动 | 认知自由，行动受托 |
| 像朋友是否需要主动联系 | 第一阶段不主动，新互动由用户发起 |
| 原始数据不长期保存是否会失忆 | 原始感知短暂，关系、任务和提炼记忆连续 |
| 继续旧对话还是新建会话 | 不做会话选择；统一记忆、动态注意力 |
| 模型自行判断是否足够安全 | 模型判断意图，确定性系统管权限、状态和证据 |
| 交付由 Violet 判断还是用户判断 | Violet 判断可交付，用户最终验收 |
| 静默进化是否意味着不可见 | 不打扰但可审计；高风险事前审批 |
| 先固定一种产品是否便于验证 | 不固定产品，以通用基础设施和多样任务评估 |
| 是否按前端到企业级规划能力 | 不按品类限制，按风险、工具和证据动态决定 |
| 多 Agent 是否天然更强 | 不是；只有协调收益超过成本时组队 |
| 浏览器扩展是否是 Violet 的眼睛 | 只是增强；Mac 全局感知才是基础 |
| Mac 原生 App 是否会绑定 Apple 语音能力 | 不会；原生层只封装设备能力，Apple Speech/TTS 与端到端模型都是可替换 Adapter |
| 端到端语音模型是否仍需经过 DeepSeek | 不一定；可在当前会话替代 DeepSeek，但不能绕过 Violet Core 的身份、记忆、策略和审计 |
| 自定义音色是否要求更换整个语音架构 | 不要求；音色是能力协商，模型原生音色与独立 TTS/声音克隆可按能力切换 |
| 世界级架构是否需要立即微服务 | 不需要；契约和边界优先，模块化单体起步 |
| 公司 Devbox 是否可作云环境 | 当前可以作临时云，但必须最小数据、可迁移 |
| 真实记忆是否可进入 Devbox | 用户已确认合规；仍禁止绝对秘密和未授权敏感原文 |
| 删除后备份是否会让记忆复活 | 新备份后销毁旧备份代密钥，恢复前重放删除墓碑 |
| Violet 能否看自己的日志 | 可以只读查看脱敏运行证据，不得篡改或关闭观测 |
| 对象存储选择什么 | 火山引擎 TOS，通过 S3 Port 接入，私有桶和信封加密 |

## 7. 当前尚未锁定的技术决策

以下问题不得由后续 Agent 静默假设：

- 正式多模态模型供应商。
- Release 1B 最终默认语音运行时：Qwen-Audio 3.0 Realtime Plus 已作为首个端到端候选通过合成 canary，但仍需决定其是否与 Pipeline 并存，以及 Pipeline 的 ASR、文字模型和 TTS 组合。
- 实时媒体面长期采用 Core 中继，还是在具备单会话短期凭证和完整审计后允许受控直连。
- 本地唤醒词引擎。
- 任务运行时是否最终采用 LangGraph.js。
- 代码 Agent 是否采用 OpenHands 或其他引擎。
- 沙箱采用 Devbox 容器、独立远程沙箱或混合方式。
- 正式个人云供应商和迁移时间。
- Safari、Firefox 等应用增强适配器的具体交付顺序。

决策方式必须是：定义验收标准、做最小真实测试、记录证据和取舍，再写入架构文档。

## 10. 新 Agent 安全交接规则

任何新接手的模型或工程师必须遵守：

- 先读本文和三份基线文档，再读当前代码和 Git 状态。
- 不把记忆或旧会话当作当前操作授权。
- 未经用户批准，不开始实现、部署、安装、付费、发布、删除或扩大权限。
- 不读取、上传或处理保密工作内容。
- 不在 Devbox 保存绝对秘密、受控敏感原文和个人生产密钥。
- 不将 Devbox IP、公司域名、公司鉴权或内部服务写入领域核心。
- 不把 Sprinkle 扩建成 Violet 本体。
- 不把浏览器或某种产品类型作为 Violet 的能力边界。
- 不让 Subagent 默认获得完整个人记忆。
- 不允许开发 Agent 自行批准自己的交付。
- 不允许 Core 直接执行文件、终端、Git、Playwright 或其他不可信工具。
- 不用模型自信替代测试、证据和回滚。
- 不静默修改产品宪法、权限、安全或审计规则。
- 不让 Violet 获得删除、篡改、关闭或扩大观测系统的权限。
- 不因追求“世界级”而提前引入无必要的微服务、队列或平台复杂度。
- 代码和运行证据只能说明当前实现。与宪法或已批准设计冲突的代码必须视为缺陷并停止交付，不能反向覆盖文档。
- 发现新风险、失败模式或推翻旧决策时，必须更新本文。
