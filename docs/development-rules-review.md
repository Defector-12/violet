# 开发规则审计与处理记录

> 2026-09-07。本文记录规则审计结果和处理边界，不是 Agent 的规则文件。

## 已处理

- 新增根目录 `AGENTS.md`，作为唯一的项目级长期规则入口。
- `AGENTS.md` 只记录自主执行、权限、安全、隐私、变更范围和验证原则，不记录 Release
  状态、模型版本、部署哈希、测试数量或临时故障。
- 删除 2026-09-03 整包引入的 25 个通用项目 Skill。它们共 7,644 行，与平台已有能力
  重复，触发范围过宽，并包含不适用于 Violet 的 Web、npm、GitHub Actions 和团队发布
  假设。
- 删除随上述通用 Skill 生成但未纳入版本控制的 `skills-lock.json`。
- 一并消除了 19 处指向 7 个不存在的 `.trae/references/*.md` 文件的引用，以及对
  `AskUserQuestion`、`/build`、`/review`、`/loop` 和 `agents/` 等当前环境不存在入口
  的依赖。
- `architecture-direction.md` 不再维护动态发布流水账；当前实现、部署、测试和门禁由
  对应验收文档统一管理。

## 全局配置

- 未直接修改产品管理的内置 Skill 文件；通过 `~/.trae-cn/skill-config.json` 禁用
  `TRAE-debugger`，避免其强制 HTTP 插桩、重复用户复现和确认后清理流程自动触发。
- 同样禁用与 `bits-code-guard` 重叠的 `TRAE-code-review`，代码审查只保留一个默认入口。
- 用户安装的 `ponytail` 已改为仅在用户明确调用时启用，并取消跨请求常驻、固定输出长度
  和限制测试框架的规则。
- 用户安装的 `karpathy-guidelines` 已改为仅在用户明确要求额外谨慎审查时启用，不再与
  项目长期原则重复触发。

## 未修改

- TRAE 为当前工作区生成的 Code Mode、Computer Use、Context7 和 Record & Replay
  元数据不是仓库配置，不手工修改生成文件。仓库当前没有 `.mcp.json`。
- 运行时视觉 Prompt 暂不在规则清理中改动。当前工作区存在进行中的视觉定位诊断代码；
  Prompt 变化会改变模型行为，必须作为独立实验，用固定样本和真实多次回放验证。

## 后续规则

- 只有出现稳定、重复且项目特有的工作流时，才新增 Violet Skill；单次经验写入文档或
  测试，不为其创建 Skill。
- 新 Skill 必须有窄触发条件、真实可用的工具、完整引用和退出条件，不得要求自动提交、
  安装依赖、修改全局配置或把可自动完成的复现交还用户。
- MCP 按任务启用并保持最小权限。项目若需要固定 MCP，应使用仓库级配置并锁定版本，
  不使用运行时下载的 `@latest`。
- 确定性安全边界保留在代码中；模型 Prompt 负责表达目标和证据语义，不替代权限、
  隐私、输入校验或发布门禁。

## 保留原则

保留隐私过滤、绝对秘密阻断、明确授权、当前轮次绑定、失败关闭、不损坏用户工作、
真实证据、统计评估和用户最终验收权。规则收敛降低的是流程噪声，不是质量或安全标准。
