当前运行与发布门禁见 [Release 1C 验收](../release-1c-acceptance.md)。

## 预期与实际

用户在 Trae 集成终端选中了打印输出：

```sh
pnpm --filter @violet/core test \
  -- realtime-session.test.ts
```

Violet 却解释了上方用于生成该输出的 `printf`。这属于错误放行，不是成功识别。
Trae 终端没有 `AXSelectedText`，因此此场景走截图；禁止用模拟复制作为旁路。

最后一次冻结鼠标约为 `(0.03655, 0.91234)`。旧日志只保存元数据，且曾在复测前清空，
没有原始图片、准确转写和模型答案，因此不能声称三次模型输入相同。

## 同图回放

助手在同一终端重建相同选区，保存经过本地隐私过滤的样本。
`.local-acceptance/pointing-replay-controlled/` 是受控样本。早期鼠标落在聊天区的
无效控制样本已删除。这是重建画面，不是恢复了用户当时那一帧。

| 方案 | 已核对结果 |
|---|---|
| 旧 Adapter + 带环图片 | 0/3，含一次超时 |
| 旧 Adapter + 无环图片 | 0/3，仍错认相邻命令或虚构文字 |
| high detail + temperature 0 + JSON mode | 0/3 |
| 1200 x 800 局部图，模型选择坐标系 | 已核对前三条均失败；未取得完整五次结论 |
| 1200 x 320 局部图，固定局部坐标系 | 0/5 严格通过；4/5 逐字正确，框仍不稳定 |
| 连通蓝色选区紧裁，模型行结构 | 10 次中严格通过 6 次；2 次空格差异、1 次低置信拒绝、1 次超时 |
| 同一正确 grounding 经 Qwen 交付 | 3/3 正确解释目标命令；均为自然改写，不是逐字复述 |

通过标准必须同时满足：Core ready、`target.text` 逐字相同、目标框位于人工标注选区内。
不能放宽置信度或框门禁，也不能忽略缩进后宣称逐字正确。固定图片回放覆盖 Adapter
与 Core grounding；Qwen 单独覆盖了真实供应商输出，但仍不等于麦克风、WebSocket、
Mac UI 和播放的完整设备闭环。

## 本地候选与已证实修复

- 像素回归证实定位环会覆盖文字笔画及已遮黑区域；已删除绘环，保留坐标和隐私遮挡。
- 同一次请求发送全屏和由冻结鼠标确定的局部图。选区问题仅在“问题语义、鼠标和宽扁
  连通蓝色像素”共同成立时使用高亮框并紧裁；否则回退模型局部框。
  不恢复“先猜框、再按错误框裁剪、再调用模型”的旧方案。
- Core 只容许一个原图像素的坐标量化误差，仍拒绝明显偏离。
- 保留文本空白；修复小图跳过坐标校验；不再向硬编码调试 IP 发送 fire-and-forget 请求。
- 显式验收模式只保留下一次合规图片输入，附问题、轮次、hash，不含 OCR、音频或凭证。
- 回放记录全部尝试及失败，结果文件不覆盖。普通使用仍不记录屏幕。

## 结论与后续

随机性确实存在，但不是充分解释。更直接的工程缺口是证据图的小字辨识与选区定位不可靠，
结构门禁不足以证明选对，而且之前没有建立可回放的输入。让用户反复补日志是开发流程问题。

下一步由用户做一次真实终端验收。当前验收 App 已开启一次性样本录制，失败时先回放。
非默认高亮色、按钮、徽标、长选区及完整设备链路仍按发布矩阵验证。诊断关闭时删除本机及远端私有
图片与结果，保留本文的无敏感内容结论；不要提前销毁失败证据。
