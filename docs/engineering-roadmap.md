# Violet 工程路线

本文维护能力演进顺序和后续验收目标。1A—1D 已交付，下一阶段为 1E；
实际部署与测试证据见 [Release 1D 验收](./release-1d-acceptance.md)。
后续章节是目标，不是现有能力，也不是未经评估的工期承诺。

## 路线目标

自然交流 → 理解当前处境 → 可靠使用过去信息 → 判断聊天、回答或行动 →
持续执行、验证和交付 → 在治理边界内扩展能力 → 跨设备保持同一身份。

每次交付都应可独立使用，后续版本停止时已有能力仍然有效。核心采用模块化单体，
领域不依赖框架和供应商；按真实需求增加隔离 Worker 和适配器。
产品边界见 [产品宪法](./product-philosophy-and-constitution.md)，系统边界见
[架构方向](./architecture-direction.md)，当前目录和开发命令见 [README](../README.md)。
路线不重复维护这些合同。

## 第一阶段：Violet 出生

第一阶段结束时，用户可以在 Mac 任意可见界面唤出同一个 Violet，自然聊天或指向
当前内容提问；Violet 能跨重启记住可靠信息，管理持久目标，调用受控工具完成并验证
真实委托，同时隔离保密工作区。

不包含多用户、商业化、第二设备、未唤醒时持续感知、保密工作内容处理，以及自主修改
安全或价值宪法。核心能力不得依赖公司内部专有服务，Devbox 不保存真实高敏隐私和
绝对秘密，不承诺尚无证据的任意技术栈能力。

| 1B · Presence | 原生 Mac、快捷键、实时语音、打断、重连和生命周期控制 | [1B 验收](./release-1b-acceptance.md) |
| 1C · Sight / Natural Pointing | 手动 Context、本地唤醒、按需完整单屏视觉问答、本机隐私过滤 | [1C 验收](./release-1c-acceptance.md)、[Natural Pointing 合同](./natural-pointing-handoff.md) |
| 1D · Continuity | 统一有界上下文、明确与自动记忆、来源召回、纠正删除和恢复防复活 | [1D 规格](./release-1d-spec.md)、[1D 验收](./release-1d-acceptance.md) |

1A 历史基线（2026-08-19）：20 轮真实 DeepSeek 对话、40 条加密事件恢复、
Core/PostgreSQL 重启、缺钥 sealed 回退、两次整台 Devbox 重启、Token 到期拒绝、
LGTM 白名单、Mac 加密备份、TOS 最小权限与版本清理、真实上传下载、无网络空库恢复和
每日加密备份调度均通过。原运维目标为 RPO ≤ 24 小时、隔离恢复 ≤ 30 分钟；
该历史记录不代表今天重新测量。

1C 用户已接受当前唤醒与视觉体验。整机睡眠、系统撤权、Vision 处理中锁屏/睡眠、
生命周期 50 次矩阵、扩大唤醒及视觉样本仍按
[已后置工作](./release-1c-acceptance.md#已后置的工作) 管理；延期不等于通过。
唤醒优化的原量化目标为 100 正样本成功率 ≥ 95%、1000 负样本误触发 ≤ 1 次、
8 小时办公误触发为 0。视觉扩展目标为 50 个跨应用样本准确率 ≥ 90%、明确框选坐标
正确率 100%、受控敏感内容默认遮挡召回率 ≥ 95%，不以现有抽样外推任意界面表现。

Qwen Audio 是默认实时运行时，`Paraformer → DeepSeek → CosyVoice` 是显式降级基线。
更换默认供应商时，重新比较同一组中英文、混合语言、停顿、噪声、打断和追问样本：
首音频延迟、VAD/回声、最终转写和账本、音色、工具和治理、地域/留存/费用、弱网与取消。
协议、来源及审计不可靠的候选不得承载正式会话，不在会话中静默切换供应商。

### Release 1E: Violet Agency

**用户可获得**

Violet 根据自然表达判断是聊天、直接回答还是建立持久目标。对于长任务，简短说明
理解和计划后安静执行；只有越过安全边界、真正阻塞或完成交付时打断用户。

**建设内容**

- 建立 Goal、Delegation Contract、Task、Checkpoint、Approval、Evidence 和 Artifact
  领域模型；持久任务支持中断、恢复、重试和重新打开。
- 自动恢复分类故障、产生新证据并改变方案；无新证据的重复尝试停止。
- 按任务选择直接执行、单个专业 Agent 或临时 Subagent 团队；每个成员只获最小上下文、
  权限、预算和契约，用户始终面对一个 Violet。
- 建立工具注册入口，首批覆盖 Web 研究、文件、受控终端、Git 和 Playwright。
- 建立最小隔离 Worker，与 Core 分进程、网络和凭证；文件、终端、Git 和浏览器调用
  只在独立临时工作区与容器内执行。
- Worker 默认无个人记忆、TOS、数据库、模型密钥或本机访问；任务通过短期能力令牌
  获得最小权限。建立四层权限门禁和持久审批。
- 记录进度、停止、取消、阻塞与交付状态。

**验收**

- 长任务跨 Core 重启从检查点继续，等待审批后可以隔日继续。
- 临时错误可恢复，永久错误进入可恢复的阻塞状态；任务的上下文、工作区、权限和预算
  互不污染。
- 一个复杂任务动态组建至少两个职责不同的 Subagent，由 Violet 汇总并独立验证。
- 20 次 Core/Worker 故障注入中，已完成步骤不重复执行，均恢复或进入可解释阻塞。
- 50 条越权调用全部被拒绝；Core 直接执行终端、文件、Git 或浏览器操作的数量为 0。
- Worker 不能读取其他任务工作区、个人记忆、PostgreSQL、TOS 或未授权网络目标；
  隔离逃逸成功数量为 0。

**回滚**

任务运行时更换或升级不改变领域事件格式。任务可回到最近健康检查点，
不可回滚的操作必须在执行前审批。

### Release 1F：Violet Delivery

**用户可获得**

接受真实开发需求，自主完成研究、项目理解、开发、测试和可用交付；用户无需逐项测试、
截图和转述 Bug。验收任务来自当时的真实需求，不固定为某种产品或技术栈。

**建设内容**

- 在 1E Worker 上接入通过 Port 封装的成熟代码 Agent，不改变 Core/Worker 边界。
- 每项任务使用独立 worktree、分支及容器或沙箱。
- 贯通官方资料研究、开发、审查、修复、单元/集成/UI/端到端/安全验证。
- 开发 Agent 不批准自己的结果；独立验证者产出 Artifact 与 Evidence Package。
- 支持预览部署、健康检查和回滚。发布、费用、正式身份、生产及新增权限仍须事前审批。

**验收**

- 先说明目标、交付物、主要路径与打扰条件，再自主执行到真实使用路径验证。
- 独立验证发现的问题须修复、由用户接受为限制或明确阻塞交付，不人为制造 Bug。
- 证据包含需求映射、测试、UI/运行记录、安全检查、部署状态、已知限制和回滚方法。
- 交付可直接体验，用户不满意时重新打开原目标，无需重述背景。
- 全部明确验收标准通过；未解决 Critical/High 安全问题和未披露已知问题均为 0。

**回滚**

开发工作区与用户主分支隔离；部署前保留上一健康版本，健康检查失败自动回滚。

### Release 1G：浏览器增强与出生验收

**用户可获得**

Sprinkle 作为结构化浏览器感官接入 Mac 网关；其他应用继续使用全局屏幕感知。
第一阶段完成一周个人真实连续使用验证。

**建设内容**

- Context Envelope v1 冻结后改造 Sprinkle，抽取文章解析、选词、图片及区域框选能力。
- 将 `PageContext` 映射到 `browser.document` 和焦点 Artifact，融合并去重浏览器与
  Mac 证据。
- 扩展不承载 Violet 身份、长期记忆或模型密钥；数据先到 Mac 网关，不直接发送云端。
- 保持 Chrome/Edge 能力，为 Firefox/Safari 建立适配边界。

**出生验收**

- 覆盖聊天、任意界面问答和真实委托；跨关闭延续、通过记忆减少解释、工具可用交付、
  纠正后改善四类体验各至少一次。
- 保密工作区无内容出境；用户明确感到沟通更快、理解更深、能解决需求。
- 一周至少 30 次真实互动，无需搬运上下文或重述即可闭环的比例 ≥ 70%。
- 上下文、记忆或工具错误均诚实暴露，不确定性/失败披露率 100%，不虚构完成。

**回滚**

保留 Sprinkle 原仓库和稳定版本；迁移不影响现有阅读工具，适配器失败退回 Mac 感知。

### 依赖与验证

已有 Node/pnpm、Swift、PostgreSQL、DeepSeek、DashScope、TOS、设备 Keychain、
Devbox SSH/Docker 和双远端。具体版本以仓库配置为准；正式分发前再决定 Apple
Developer 签名与公证。权限和付费资源按当次委托处理。

验证入口集中在 [README](../README.md#开发) 和 [测试规范](./testing/README.md)。
现有测试使用 Vitest/Swift Testing，没有独立 `test:integration` 或 `test:e2e` 命令。
启动、备份、恢复脚本会改变运行状态，不能作为无副作用的本地检查。
CI 尚未实现的门禁不能仅因列入路线就视为已有。

## 第二阶段：可依赖的行动者

进入条件：出生验收通过，记忆误召回与任务失败已有观测基线，Devbox 可稳定恢复。

扩大工具、MCP、Agent 和部署适配器；改进多任务、动态团队、长时间执行与恢复；
建立持续回归、红队、安全审计和成本治理；支持更多开发、研究和自动化任务；
条件具备时演练并迁移到正式个人云。

完成信号：不同技术栈的成功来自同一基础设施，失败可解释、可恢复、可回滚。

## 第三阶段：可治理的自我进化

进入条件：工具注册、权限、证据和回滚稳定，已能可靠完成开发与验证。

自动发现能力缺口，搜索、评估、沙箱安装和版本化 Skill/MCP/工具；
自动生成或接入的新能力经独立评估后启用；只在候选环境修改自身非安全核心，
持续观测效果、费用和退化。

完成信号：低风险进化可静默进行且可审计，高风险变更事前审批，失败升级不损害身份、
记忆和安全核心。

## 第四阶段：跨设备的同一个 Violet

进入条件：身份、记忆、任务、协议与设备授权已在 Mac 稳定。

接入手机、手表、耳机、眼镜及未来硬件；设备只扩展感官与行动，不复制身份。
支持连续对话、任务接力、一致权限，并按设备能力选择最小充分交互。

完成信号：任何设备唤醒都是同一个 Violet；丢失或撤销设备不损害连续性或泄露其他数据。

## 第五阶段：通用创造与长期伙伴

进入条件：多设备、多任务和长期使用已证明可信，用户愿意扩大委托。

承担跨领域、跨环境的长期目标，对问题定义、研究、设计、开发、部署与运维负责，
形成探索、学习和创造的长期闭环。仅在用户明确选择后评估有限主动联系，
默认仍由用户发起关系。

完成信号：不依赖固定页面、产品类型或逐项目补丁，长期保持认知自由、行动受托和
结果负责。

## 阶段治理

- 路线不是能力上限；证据和权限充分时可提前承担更复杂任务。
- 模型自报能力不替代测试、安全、备份和回滚门禁。
- 开始每阶段前以真实数据复核风险与依赖，可调整顺序，不静默改变产品宪法。
- 完成后将实际变化和工程教训写入 [历史记录](./历史记录.md)，当前交付证据写入对应
  验收文档；临时进度不进入永久工程规则。
