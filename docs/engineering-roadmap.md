# Violet 工程路线

> 状态：执行路线基线。阶段按能力成熟度推进，不按产品类型限制 Violet。本文中的顺序是依赖顺序，不是未经评估的工期承诺。

## 1. 路线目标

终局不是完成一个功能列表，而是逐步建立同一个 Violet：

```text
自然交流
→ 理解当前处境和用户意图
→ 记得共同经历并正确使用
→ 自主选择聊天、回答或行动
→ 持续执行、验证和交付
→ 在治理边界内扩展能力
→ 跨设备保持同一身份
```

第一阶段必须交付一个最小但完整的 Violet，而不是若干互不相连的 Demo。

## 2. 工程原则

- **契约优先**：客户端、后端和 Worker 只通过版本化协议通信。
- **领域内聚**：身份、记忆、目标、授权、证据等领域模型不依赖框架和供应商。
- **前后端分离**：客户端不得直接访问数据库和执行环境，也不得持有模型供应商长期凭证；任何未来的供应商直连媒体路径必须由 Core 签发单会话短期能力并满足出境、吊销与审计策略。
- **实时会话可替换**：语音交互以版本化会话协议连接设备与 Core，同时支持分离式 Pipeline 和端到端实时模型，不把听、想、说固定到 Apple、DeepSeek 或单一供应商。
- **模块化单体起步**：先确保边界清晰，再按真实需求拆服务。
- **全局感知优先**：Mac 对任意可见内容提供通用感知，应用适配器只增强精度。
- **可迁移优先**：Devbox 是当前环境，不进入领域模型和客户端协议。
- **证据优先**：模型自信不是完成证明，交付必须经过独立验证。
- **安全默认拒绝扩大权限**：权限、费用、隐私和不可逆影响必须经过确定性门禁。
- **纵向交付**：每个阶段内版本都可独立使用；后续版本停止时，已有系统仍然有效。
- **线性 Git 历史**：保护主分支，变更通过短分支、PR、审查和可回滚提交进入。

## 3. 目标工程结构

```text
Violet/
├── apps/
│   ├── macos/                 Swift 原生身体与本机网关
│   ├── dev-cli/               1A 文字入口与长期运维诊断工具
│   └── browser-extension/     Sprinkle 演化后的浏览器增强感官
├── services/
│   ├── core/                  云端接入层、应用层与领域核心
│   └── worker/                沙箱、Agent、验证、部署与运维
├── packages/
│   ├── protocol/              JSON Schema 事实源、OpenAPI 与生成 SDK
│   ├── domain/                纯 TypeScript 领域模型
│   ├── policy/                确定性权限与安全策略
│   ├── memory/                记忆写入、检索与评估
│   └── evals/                 对话、记忆、任务和交付评估
├── infra/
│   ├── compose/               可迁移的本地与 Devbox 部署
│   ├── migrations/            PostgreSQL 迁移
│   ├── backup/                导出、备份与恢复
│   └── observability/         日志、指标与追踪
├── docs/
└── scripts/
```

## 4. 第一阶段：Violet 出生

### 4.1 阶段结果

第一阶段结束时，用户可以在 Mac 任意可见界面唤出同一个 Violet，自然聊天或指向当前内容提问；Violet 可以跨重启记住可靠信息、管理一个持久目标、调用受控工具完成并验证一项真实委托，同时严格隔离保密工作区。

### 4.2 明确不包含

- 多用户、团队空间、商业化和计费。
- 未唤醒时持续感知或主动发起新互动。
- 手机、手表、眼镜等第二设备。
- 处理公司保密工作内容。
- 依赖公司内部专有服务才能运行的核心能力。
- 自主修改安全、权限、审计和价值宪法。
- 对所有技术栈和企业级项目能力作无证据承诺。
- 将真实高敏隐私、个人生产密钥或绝对秘密存入 Devbox。

### 4.3 第一阶段发布序列

#### Release 1A：Violet Seed

**用户可获得**

通过 Mac 上的 TypeScript 开发客户端与 Devbox 上的 Violet 进行连续文字对话；服务重启后身份和对话事件仍然存在。该版本已经是可使用的云端 Violet 种子，不依赖后续 Mac UI 才能工作。

**当前证据**

截至 2026-08-19，代码、Devbox 部署、20 轮真实 DeepSeek 对话、40 条加密事件恢复、Core/PostgreSQL 重启、缺钥 sealed 回退、两次整台 Devbox 物理重启、Token 到期拒绝、LGTM 白名单、Mac 加密备份、TOS 最小权限与版本清理、真实上传下载、无网络空库恢复和每日加密备份调度均已通过。

**建设内容**

- Git 仓库已在 Mac 初始化，内部 `bits` 与 GitHub `origin` 保存相同的 `main` 提交；Devbox 在 `bits` 上使用短分支和 MR 进入受保护主分支，合并后的确定提交同步到 GitHub 可迁移镜像，Mac 与 Devbox 使用独立克隆。
- 建立 pnpm workspace 和 Swift 工程边界。
- 建立 `apps/dev-cli`，只通过生成 SDK 和 SSH 隧道进行流式文字对话、健康检查与诊断，不直接访问数据库。
- 建立 `packages/protocol`：JSON Schema 2020-12 是数据与事件结构的唯一事实源，OpenAPI 3.1 引用这些 Schema 描述 HTTP API。
- 生成 TypeScript SDK，并验证 Swift `Codable` 模型生成或兼容。
- 建立 `services/core` 模块化单体：
  - Identity
  - Conversation
  - Event Ledger
  - Model Gateway
  - Policy
- 建立 PostgreSQL 迁移、事件表、身份表和最小对话存储。
- 对话、事件和身份内容在写入 PostgreSQL 前使用应用层信封加密。
- 建立模型供应商 Port；永久保留确定性测试适配器，并接入用户选择和授权的 DeepSeek `deepseek-v4-flash` 文字模型适配器。供应商不可用时明确失败，不自动切换。
- 建立 Docker Compose：Core、PostgreSQL、OpenTelemetry Collector 和 Grafana LGTM。
- 在 Devbox 部署，同一份 Compose 可在空白 Linux 环境启动。
- Core 监听容器内部接口，但 Devbox 宿主机只在 `127.0.0.1` 发布端口，Mac 只通过 SSH 隧道访问；PostgreSQL 只存在于容器内部网络。
- 开发期由 Mac 生成设备令牌并保存到权限为 `0600`、被 Git 强制忽略的本地 `.env`；Core 只获得令牌哈希和到期时间，认证时必须执行到期检查。原生 Mac App 建立后迁移到 Keychain。
- 内容密钥、模型 API Key 和 TOS 凭证由 Mac 注入 Devbox 临时内存文件系统，只读挂载给对应进程，不写入 Git、镜像、数据库、日志或备份。
- ready Core 只从 `/dev/shm` 读取运行秘密；独立 sealed 回退 Core 只读取不可逆 Token 哈希和到期时间。Devbox 重启后重新获得 Mac 密钥注入前不得读取或处理个人内容。
- 使用 Mac 私钥对应的 X25519 公钥、HKDF-SHA256 和 AES-256-GCM 流式加密 PostgreSQL custom dump，再保存到火山引擎 TOS 私有普通桶；同时在 Mac 保留一份加密备份。
- 建立结构化日志、请求 ID、事件 ID、健康检查和错误分类。OpenTelemetry Collector 通过字段白名单和脱敏后写入 LGTM。
- 建立用户运维视图和 Violet 只读诊断 Port；后者只返回与当前目标相关的脱敏运行证据。

**验收**

- `docker compose config` 无错误。
- `docker compose up -d` 后所有健康检查通过。
- `pnpm check` 完成类型检查、单元测试、协议兼容检查和构建。
- 同一 Violet 身份连续完成 20 轮对话，顺序、角色和内容恢复一致率为 100%。
- 分别重启 Core、PostgreSQL 和整台 Devbox 后验证：未注入密钥时 100% 拒绝内容访问，注入后身份和事件完整恢复。
- 未认证、错误令牌、过期令牌和绕过 SSH 隧道的请求 100% 被拒绝。
- 从 Mac 通过 SSH 隧道访问 Core；更换 Devbox 地址不修改领域代码或重新生成协议。
- 切换模型适配器不修改领域核心。
- 每次数据库迁移前备份，并至少每日备份；RPO 不超过 24 小时。
- 从空白 Linux 环境和全新数据库恢复加密备份，30 分钟内达到健康状态，记录数量与内容哈希 100% 一致。
- 对源码、Git 历史、镜像、数据库、日志和备份执行密钥扫描，明文密钥数量为 0。
- 抽查全部 1A 遥测字段，允许列表外字段、对话原文、Prompt、回复、请求头和凭证数量为 0；详细日志和 Trace 保留 30 天，聚合指标保留 90 天。
- 未经 Core 代理，`dev-cli` 无法访问 PostgreSQL、TOS 和模型供应商。

**回滚**

- 每次数据库迁移提供向前修复方案和备份恢复说明。
- Core 镜像保留上一健康版本；失败时回滚镜像并恢复兼容数据库快照。
- 回滚不得恢复已删除内容；恢复流程必须先应用删除墓碑和密钥注册表状态。

#### Release 1B：Violet Presence

**用户可获得**

在 Mac 上通过全局快捷键或点击唤出 Violet，立即得到“我在”“嗯哼”等本地短回执，并可以使用文字和语音与云端同一 Violet 对话。关闭浮层只结束在场，不结束已建立的后台任务。

**当前实现证据**

截至 2026-08-20，首个纵向切片已完成本地实现：`RealtimeSession v1` 协议、Core WebSocket 认证与 sealed 门禁、确定性实时 Adapter、最终用户/助手事件落账、Swift 原生菜单栏 App、Keychain 读取与 stdin 迁移工具、可选 SSH 隧道、文字流式 UI、全局快捷键、睡眠与锁屏停止、`AudioIOPort` 和隔离测试 Adapter。TypeScript 11 个测试文件共 37 个测试、Swift 6 个测试通过，ad-hoc 签名 `.app` 构建与签名校验通过。

该证据不代表 Release 1B 已完成：App 尚未在用户桌面真实启动；麦克风、快捷键、锁屏、睡眠和视觉体验尚未进入用户批准的验收窗口；真实 Pipeline 与端到端实时模型尚未评估或选型。

**建设内容**

- `apps/macos` 使用 Swift、SwiftUI 和 AppKit。
- 实现菜单栏入口、全局快捷键、轻量存在信号和浮层。
- 实现本地即时唤醒回执，不等待云端响应；回执音频是可替换资源，不绑定后续会话音色实现。
- 建立 Mac `AudioIOPort`，封装麦克风、扬声器、耳机、静音、回声处理、设备切换和立即停止，不在 UI 或状态机中直接依赖 Apple Speech、AVSpeechSynthesizer 或模型 SDK。
- 在 `packages/protocol` 建立 `RealtimeSession v1` 双向事件：会话与能力协商、音频分片、可选文字输入、VAD、输入转写、文字与音频输出、打断、完成和错误。
- 在 Core 建立实时会话编排器和 `RealtimeConversationPort`，永久保留确定性实时测试适配器，并允许接入：
  - Pipeline Adapter：ASR → 文字认知模型 → TTS。
  - Integrated Realtime Adapter：端到端模型直接完成音频理解、推理以及文字和音频输出。
- 无论使用哪种 Adapter，Core 始终负责身份、相关记忆、授权、策略、审计和最终事件落账。端到端模型可以替代当前语音会话中的 DeepSeek，但不能替代 Violet Core。
- 建立能力描述和音色配置。端到端模型支持目标音色时使用其音频；只支持预设音色时允许请求文字输出并交给独立 TTS Adapter。
- 只持久化经过授权的最终用户转写、最终回复和脱敏用量元数据；临时转写、模型内部推理和原始音频分片不进入事件账本、记忆、日志或 Trace。
- 实现设备身份、Core 连接、断线重连和离线状态。
- 使用 Keychain 保存设备凭证，模型密钥不进入 Mac UI。
- 实现本机紧急停止、设备断开和权限撤销。
- 定义本地唤醒词引擎 Port。
- 建立隔离测试模式：使用合成音频、静音播放器、假 Keychain、假快捷键和确定性 Core，不注册真实全局快捷键、不占用真实麦克风、不播放声音、不锁屏或睡眠，也不控制用户正在使用的应用。

**实时运行时决策门**

在真实语音运行时进入 1B 交付范围前，使用同一组中文、英文、中英混合、停顿、噪声、打断和连续追问样本，对至少一个 Pipeline 基线与一个端到端实时候选进行实测。记录并比较：

- 端到端首包和首段可听音频延迟。
- VAD 误切断、用户打断和回声重触发。
- 最终转写与最终回复是否稳定可取得并写入 Violet 事件账本。
- 音色能力是预设、参数化设计还是声音克隆，以及目标音色不可用时的降级方式。
- 工具调用、相关记忆注入、内容治理、供应商留存、费用和地域可用性。
- 弱网重连、取消、会话过期和供应商故障语义。

若端到端候选不能稳定提供最终转写、执行 Violet 策略或完成审计，则不得因为延迟或音色更好而直接承载 Violet 会话；应退回 Pipeline 或只把它作为语音输入/输出能力。选型结果和证据必须写回总体架构与历史记录。

**唤醒词决策门**

Release 1B 必须保留全局快捷键作为可靠入口。语音唤醒候选必须满足：唤醒前音频不上传、不保存，办公环境误唤醒率可接受，并能在目标 Mac 上稳定运行。若候选未通过本地测试，Release 1B 先以快捷键和点击交付，语音唤醒继续留在第一阶段，未通过前不得声称完成“叫一声 Violet 即出现”的目标。

**验收**

- `swift test` 全部通过。
- Mac App 冷启动、后台驻留、睡眠唤醒和网络重连正常。
- 全局快捷键在常见前台应用中可用。
- 在 100 次本地触发中，视觉反馈和短回执延迟的 p95 不超过 200ms，成功率为 100%。
- 系统静音或勿扰时只显示视觉反馈；耳机连接时不外放。
- 云端离线时明确显示离线，不伪装成思考。
- `RealtimeSession` 的乱序、重复、取消、断线和未知事件测试全部拒绝错误状态转换；更换确定性、Pipeline 或端到端 Adapter 不修改 Mac UI 状态机和 Violet 领域模型。
- 在稳定网络的 30 次真实语音交互中，用户停止说话到首段可听回复的 p95 不超过 2 秒；超过门槛时必须展示仍在处理的真实状态，不能伪装成本地响应。
- 在 30 次用户打断测试中，当前音频播放在 300ms 内停止，1 秒后继续播放已取消响应的次数为 0。
- 30 次真实语音交互的最终用户转写和最终回复均可由事件账本恢复；原始音频分片、临时转写和模型内部推理的持久化数量为 0。
- 供应商不可用或能力协商失败时保留文字入口并明确失败，不静默切换到未经授权的模型、地域或音色。
- 在 50 次结束、锁屏和超时测试中，麦克风 1 秒内停止且不再产生音频事件，后台任务状态不丢失。
- 单元、协议和常规 UI 自动化在隔离测试模式运行，对真实全局快捷键、麦克风、扬声器、锁屏、睡眠和用户前台应用的操作数量为 0。真实设备、全局快捷键、音频、锁屏和睡眠测试只在用户明确同意的验收窗口执行。

**回滚**

- Mac App 保留上一签名可运行版本。
- 新协议无法协商时退回上一兼容协议，不发送未知数据。
- 新实时模型 Adapter 失败时可停用并退回文字会话或上一健康语音 Adapter，不迁移或重写已有对话数据。

#### Release 1C：Violet Sight

**用户可获得**

在桌面、图片预览、PDF、IDE、浏览器和其他可见窗口中，用户可以说或输入“这个”，通过当前窗口、选区或区域框选让 Violet 理解所指内容。没有应用适配器时仍能工作，有适配器时获得更高精度。

**建设内容**

- 实现 Context Envelope v1：
  - `screen.snapshot`
  - `focus.region`
  - `focus.text`
  - `audio.utterance`
  - `app.state`
- Mac 端接入 ScreenCaptureKit、Accessibility 和区域框选。
- 建立当前应用、窗口、屏幕和用户焦点识别。
- 建立 OCR / 视觉模型 Port 与一个可用适配器。
- 实现证据优先级、完整度和置信度。
- 实现保密应用、目录和窗口隔离策略。
- 使用设备端规则、密码字段识别和本地 Apple Vision OCR，仅为阻断而检测绝对秘密和受控敏感信息；检测结果不包含原文，不上传、不记录、不进入模型。
- 为感知会话建立开始、缩小、扩大、停止和过期机制。
- 只上传本次授权范围内的内容。
- 接入 TOS：使用私有普通桶、S3 V4、Virtual-hosted Style、限定桶前缀的 IAM 子账号、客户端信封加密和 TOS 服务端加密。
- TOS 开启版本控制和临时对象生命周期；用户可删除内容所在桶不得开启 WORM/Object Lock。

**验收场景**

- 桌面框选一个文件或图标并提问。
- 在图片预览中框选局部并提问。
- 在 PDF 阅读器中针对当前页或选区提问。
- 在 IDE 中针对选中代码或当前窗口提问。
- 在无 Sprinkle 的浏览器中通过屏幕感知提问。
- 进入保密工作应用后，云端只收到“感知被本地策略阻止”。
- 撤销屏幕权限或结束会话后，不再产生感知事件。
- 读取不完整或置信度低时，Violet 明确说明不确定。
- 50 个覆盖桌面、预览、PDF、IDE 和浏览器的指向测试中，当前对象识别准确率不低于 90%，用户明确框选范围的坐标传递正确率为 100%。
- 保密应用、密码字段及绝对秘密合成测试集的内容出境数量为 0；受控敏感信息测试集的默认遮挡召回率不低于 95%。
- 结束、锁屏、超时和撤权后共 50 次测试中，过期 Context 被云端接受的数量为 0。

**回滚**

- 任一感知适配器失败时退化为用户主动框选，不扩大自动读取范围。
- 策略引擎不可用时默认停止数据出境。

#### Release 1D：Violet Continuity

**用户可获得**

Violet 跨关闭、重启和不同场景保持同一身份，能正确使用过去信息减少解释；用户可以查看、编辑和删除记忆。低置信度时 Violet 会承认不确定。

**建设内容**

- 建立事件账本和认知模型双层结构。
- 实现核心、情景、任务、知识、程序和自我记忆类型。
- 每条记忆保存来源、时间、类型、置信度、敏感级别、版本和影响范围。
- 异步提取长期记忆，不阻塞当前对话。
- 实现新增、确认、补充、冲突、取代和失效语义。
- 建立关键词、语义、实体、时间和任务相关性的混合检索。
- 建立用户记忆管理界面和来源追溯。
- 实现编辑、删除及向索引和衍生记忆的传播。
- 实现删除契约：
  - 请求接受后立即停止检索和使用。
  - 24 小时内清除源内容、摘要、索引、向量、关系、缓存、任务副本、详细观测记录、TOS 全部对象版本、删除标记和未完成分片。
  - 审计只保留不含内容和语义的删除 ID、时间、设备、作用域类别、状态和策略版本，保留至整个实例被删除。
  - 销毁对应内容数据密钥；生成删除后的新备份，再销毁删除前所有备份代的解密密钥。
  - 备份最长保留 30 天；恢复时先重放删除墓碑并验证删除内容未复活。
  - 删除整个 Violet 实例时销毁内容、审计、对象、所有备份和根密钥。
- 建立记忆评估集，覆盖跨重启、偏好更新、矛盾、时序、误召回和应当拒答。

**验收**

- 连续使用一周，跨重启正确恢复共同经历和未完成事项。
- 至少 100 条标注记忆用例中，检索精确率不低于 95%，应当拒答的正确率不低于 95%，将无来源推断作为确定记忆引用的数量为 0。
- 20 条无关历史干扰用例中，错误使用无关记忆的数量不超过 1。
- 10 条用户纠正用例中，纠正后旧结论继续作为当前事实使用的数量为 0。
- 删除测试覆盖事件、衍生记忆、向量、缓存、任务、TOS 版本和备份恢复；在线检索立即不可见，24 小时内物理清理完成，恢复后复活数量为 0。
- 低置信度记忆以不确定方式表达；无可靠证据时回答“想不起来”。
- 记忆评估同时报告准确率、误召回率、拒答正确率、p95 延迟和 token 成本，并保存基线用于回归。

**回滚**

- 认知模型可由事件账本重建。
- 新检索策略效果下降时回滚索引版本，不修改原始事件。

#### Release 1E：Violet Agency

**用户可获得**

Violet 能根据自然表达判断是聊天、直接回答还是建立持久目标。对于长任务，Violet 简短说明理解和计划后安静执行；只有越过安全边界、真正阻塞或完成交付时打断用户。

**建设内容**

- 建立 Goal、Delegation Contract、Task、Checkpoint、Approval、Evidence 和 Artifact 领域模型。
- 接入持久任务运行时，支持中断、恢复、重试和重新打开。
- 自动恢复必须分类故障、产生新证据并改变方案。
- 建立动态执行决策：
  - Violet 直接完成
  - 单个专业 Agent
  - 临时 Subagent 团队
- Subagent 仅获得最小上下文、权限、预算和任务契约。
- 建立工具注册中心和首批通用工具：
  - Web 研究
  - 文件读写
  - 受控终端
  - Git
  - Playwright
- 在 `1E` 建立最小隔离 Worker：与 Core 分进程、分网络、分凭证，所有文件、终端、Git 和 Playwright 调用只能在独立临时工作区与容器中执行。
- Worker 默认无个人记忆、无 TOS、无数据库、无模型密钥和无本机访问权限；每个任务通过短期能力令牌获得最小权限。
- 建立四层权限门禁和持久审批。
- 建立任务进度、停止、取消、阻塞和交付状态。

**验收**

- 一个跨 Core 重启的长任务从检查点继续，而不是重头开始。
- 一个任务在等待审批后可以隔日继续。
- 临时错误自动恢复；永久错误进入可恢复阻塞状态。
- 无新证据的失败重试被停止。
- 多任务上下文、工作区、权限和预算互不污染。
- 一个复杂任务可以动态组建至少两个职责不同的 Subagent，并由 Violet 汇总和独立验证。
- 用户全程只面对一个 Violet。
- 20 次 Core 或 Worker 故障注入中，已完成步骤不重复执行，任务均从最近有效检查点恢复或进入可解释阻塞。
- 50 条越权工具调用测试全部被拒绝；Core 进程直接执行终端、文件、Git 或浏览器操作的数量为 0。
- Worker 无法读取其他任务工作区、个人记忆、PostgreSQL、TOS 或未授权网络目标；隔离逃逸成功数量为 0。

**回滚**

- 任务运行时切换或升级不改变领域事件格式。
- 每个任务可以回滚到最近健康检查点，无法回滚的操作必须在执行前审批。

#### Release 1F：Violet Delivery

**用户可获得**

Violet 可以接受一个真实开发需求，自主完成研究、项目理解、开发、测试和可用交付；用户不再负责逐项测试、截图和转述 Bug。

**建设内容**

- 在 `1E` 的最小隔离 Worker 上扩展成熟代码 Agent、完整验证和部署能力，不改变 Core/Worker 边界。
- 每个任务使用独立 worktree、分支和容器或沙箱。
- 接入一个成熟代码 Agent 执行引擎，通过 Port 封装。
- 建立项目理解、官方资料研究、开发、代码审查和修复链路。
- 建立独立验证者，开发 Agent 不得批准自己的结果。
- 建立单元、集成、UI、端到端和安全检查能力。
- 建立 Artifact 与 Evidence Package。
- 建立预览部署、健康检查和回滚。
- 发布、费用、正式身份、生产环境和新增权限仍需事前审批。

**任务选择原则**

验收任务来自用户当时的真实需求，不预先限定为前端、后端或某种产品。Violet 根据需求动态评估能力、风险和验证方法。产品类型只是测试样本，不成为架构边界。

**验收**

- Violet 先说明目标、交付物、主要路径和打扰条件，再自主执行。
- 自动完成项目理解、研究、实现、启动和真实使用路径验证。
- 独立验证发现的每个问题都必须被修复、经用户接受为限制或明确阻塞交付，不要求人为制造或必须发现 Bug。
- 交付证据包含需求映射、测试、UI 或运行记录、安全检查、部署状态、已知限制和回滚方法。
- 用户收到的是可直接体验的结果，而不是代码片段或待完成清单。
- 用户不满意时重新打开原目标继续修改，不要求重新描述背景。
- 全部明确验收标准通过，未解决的 Critical/High 安全问题数量为 0，未披露的已知问题数量为 0。

**回滚**

- 开发工作区与用户主分支隔离。
- 部署前保留上一健康版本；健康检查失败自动回滚。
